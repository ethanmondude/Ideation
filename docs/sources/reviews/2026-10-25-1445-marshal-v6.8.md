### Two new weak spots I found (build-brief guardrails, not score movers)
1. **Run the curve check on the owner, never on the token account.** Helius/RPC `getTokenLargestAccounts` returns token-account addresses. Associated token accounts are themselves program-derived (off-curve), so if the check is applied to that address instead of the resolved owner, every holder gets dropped and R4, R4b and R12 go silent with no error. SPEC §5.3b says "owner" and §5.4 says "+ owner lookup", which is right, but nothing tests it. Added AT-133 below.
2. **Off-curve skip hides PDA-held wallets.** A dumper holding through a multisig vault (for example a Squads vault, which is a PDA) would be skipped. This only fails safe (a missed stamp, never a false red), so accept it and state it as a known miss in the Why/FAQ text.

### Refined idea
Marshal is unchanged as a product: a free, automatic X-feed fact layer with a red "same top wallet as <earlier rug>" stamp. The refinement: every holder rule first resolves each top token account to its owner, drops owners that are off the ed25519 curve (programs, pools, vaults), then drops the labelled on-curve list (exchange hot wallets), and `r4b_red` ships on with a two-scan roll-back.
