## Claude Code build brief (Stencil v1, refined; self-contained)
**Summary.** Stencil turns any website you're signed into into a typed tool your AI agent can call, without handing over a password. You do the task once in Chrome; Stencil watches the page's own network requests, works out which request does the job and which fields are inputs, and writes a `*.stencil.json` tool file. Your local MCP server then runs that tool by replaying the site's first-party HTTP calls from inside your Chrome session (same cookies, same origin), falling back to DOM replay when a site doesn't expose a clean request. **Wow moment (one minute):** record "download October invoices" on a supplier portal, and Claude Code calls `acme_invoices({month:"2026-10"})` and gets JSON back in under a second.
**Target user.** Developers and technical operators wiring Claude Code, Cursor or custom agents into sites with no API; secondary: crypto power users automating dashboards they're logged into.
**Where it runs.** Chrome MV3 extension (recorder, runner, tool cards) + local Node MCP server (stdio) paired over native messaging. Optional hosted relay later.

**v1 features in build order (acceptance criteria):**
1. Network recorder: during Record, capture requests via `chrome.debugger` (Network domain) on the recorded tab only, plus DOM actions (click, type, select, navigate). Drop analytics, pixels, polling. AC: on 10 sample sites, the request that carries the result is in the capture 10 of 10 times.
2. Request compiler: find the request whose response holds the selected result; map user-typed values to request fields (record the task twice with different inputs and diff, as Unbrowse does); trace tokens/IDs (CSRF, account IDs) back to the response that produced them; output a request chain. AC: 7 of 10 tasks compile to a chain that replays with new inputs.
3. Tool file `*.stencil.json`: `name, description, version, origin, authority (read|write), inputs (JSON Schema), output (JSON Schema), mode (http|dom), requests[] or steps[], confirmSteps[], signature`. AC: validates against a published JSON Schema; diffs cleanly in git.
4. Runner: executes `http` mode from an extension context on the site's origin (so the browser attaches its own cookies; cookies are never read or exported), else `dom` mode with ranked locators and post-conditions. AC: http-mode median under 1s; dom-mode median under 5s for 5-step reads.
5. Local MCP server + `npx stencil init` (writes Claude Code/Cursor config, loads every tool in `~/.stencil/tools/` and `./.stencil/` in the repo). AC: new user reaches first successful call in under 3 minutes, 5 of 5 testers.
6. Tool card UI: inputs, output preview, authority, dry run. Write tools require `confirm:true`. AC: 0 of 50 confirm steps run without it.
7. `stencil test` CLI for CI: runs each tool's saved example and checks output against schema. AC: exits non-zero on schema mismatch.
8. Repair (BYO key): on failure, a small model proposes a new locator or request mapping and verifies it. AC: 7 of 10 simulated breakages fixed within 60s.
9. Importers: workflow-use JSON and Integuru-style HAR. AC: 8 of 10 samples become working tools.
10. Later (Pro, after first users): hosted relay (Cloudflare Worker + Durable Object, outbound WebSocket from the extension); credits; token.

**Out of v1:** cloud browsers, password storage, captcha solving, stealth or proxy rotation, a public library with verified stamps (Unbrowse already has one), Windows-only features, voice.
**Data sources and APIs (verified exist):** Chrome extension APIs (`chrome.debugger`, native messaging, MV3); `@modelcontextprotocol/sdk`; Chrome Web Store developer registration (one-off fee, about US$5, not rechecked tonight); Cloudflare Workers paid US$5/mo for the relay (idea bot figure, not rechecked tonight); Stripe Checkout; any OpenAI-compatible small model for repair (cap A$40/mo).
**Stack and layout:** TypeScript monorepo: `extension/` (service worker, content scripts, side panel), `mcp/` (Node 20 stdio server, CLI `init|test|import`), `schema/` (tool-file JSON Schema), `relay/` (Worker, later), `examples/`.
**Data model:** ToolFile (above); Recording {id, origin, actions[], requests[] (url, method, headers minus cookies, body template, response sample hash)}; RunReceipt {tool, version, pass, schemaMatch, ms} with no page content.
**Token integration (after 50 paying users, Ethan's call):** $STNCL on pump.fun; burn instruction with memo `stencil:<user>:<credits>` verified by the relay to credit the account; no payouts, yield, buybacks or revenue-funded burns; mint authority off; one pinned CA in the extension About page.
**Legal guardrails:** "automate your own account"; per-site opt-out list; respect site terms; never "invest", "price" or "returns" wording; token is a consumable credit; get a short legal read before launch (not legal advice).
**Unverified, mark in code comments:** that http-mode works for most portals (many sign requests or use websockets); rtrvr's free-plan MCP limits; Chrome Web Store review outcome for `debugger` permission (expect extra scrutiny; request it optionally per site).
**Launch checklist:** spike passes AC 2 and 4 on 10 sites; privacy page states cookies never leave the browser; unlisted Web Store build approved; Show HN draft for Ethan's approval; no token until paying users.
