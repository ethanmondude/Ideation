## Blind results (predictions frozen 10:41am AWST, before any label was opened)
Method: `METHOD.md`. The post rules are idea bot's saved `rules_v0.py`, unchanged (sha256 56087f56…e07d). idea bot saved no copycat-engine code, so I built the stamp from the thesis text with no tuning:
- **Candidates:** DexScreener and Jupiter search on the coin's ticker and name.
- **Signals:** S1 Jupiter verified, S2 oldest first pool, S3 most holders.
- **"Real" rule:** S1 plus S2 or S3. A variant that takes any 2 of the 3 gave identical results.
- **Mapping:** "copy" or "no confirmed real mint" counts as a flag.

#### Data model

  - `settings`: strictness, raw, local-only.
  - `rulepack_version`.
  - `free_counter[date]`.
  - `pro_token`.

  - `spend:{yyyymm}`
  - `rl:{install_id}:{date}`

- **Pro (after launch):**
  - `pro:{install_id}`: plan (card or hold), wallet (if held), expires.

#### Token integration ($CFEED on pump.fun, only after the launch gate and Ethan's pick)
- **What's on-chain:**
  - one SPL token created on pump.fun, with mint and freeze authority confirmed off;
  - a labelled dev buy of no more than 0.5 SOL from a published wallet;
  - creator fees paid to a published operating wallet used for hosting only.
  
  Nothing else runs on-chain in v1: no program, no staking, no escrow.
- **v1 mechanic: hold to unlock Pro.**
  - The website asks for a `signMessage` nonce (never a transaction).
  - The server reads the SPL balance. At or above the threshold, it issues a 30-day Pro token to the install ID.
- **v1.1 mechanic: burn your own** for deep checks, priced under Rempart's US$0.15.
  - The user signs an SPL `burn` of their own tokens.
  - The server confirms mint, amount and owner on-chain, then credits the account.
  - The public ledger links each credit to its burn signature.
- **Never:** holder payouts, buybacks, revenue share, staking yield, creator-fee buy-and-burn, Holder Rewards or Tokenized Agent. Card and USDC revenue never buys $CFEED.
- **pump.fun fees** ([fees page](https://pump.fun/docs/fees), updated 17 Oct 2026, re-read 12:32pm AWST):
  - Creating a coin carries no platform fee.
  - Bonding-curve trades pay 1.25%, of which 0.30% goes to the creator.
  - Graduation costs 0.015 SOL.
  - After graduation, the canonical PumpSwap pool pays the creator 0.95% at a market cap of 420–1,470 SOL, falling to 0.05% above 98,240 SOL.
  - Web and mobile app trades add a 0.45% Platform Fee, including the creator's first buy.
- **Dogfood:** add $CFEED to the extension's family map at launch, so its copycats get stamped from minute one.

**Summary.** Marshal is a read-only Chrome MV3 extension (Brave, Arc and Edge work; Firefox later) for desktop Solana traders who find coins on X and buy on GMGN, Jupiter, pump.fun, Axiom or Photon. #### 1. Summary and one-minute wow
Marshal is a read-only Chrome MV3 extension (Brave, Arc and Edge work; Firefox later) for desktop Solana traders who find coins on X and buy on GMGN, Jupiter, pump.fun, Axiom or Photon. On x.com it folds drainer, airdrop-lure and copy-paste shill replies into a grey bar with a reason, puts a factual pill on every CA, $ticker and token link, flags a reply CA that differs from the thread author's, shows "claimed $X · live $Y" when a post brags about market cap, and marks coins pushed by a shill ring it has seen before. When you click through to a coin page it remembers the post; if the page's mint is different, the toolbar icon turns red and a notification says "Not the mint in the post you came from (@author, 1 min ago)". Opt-in: paste a public wallet address and, on your device only, each account that sent you to a coin gets a small stamp with your own result ("led you here 3× · −1.4 SOL · 1 of 3 held 24h"). No wallet connect, no signing, no buy button, no sign-up, no LLM; post text, handles and wallets never leave the browser.

**One-minute wow:** install, open a memecoin reply thread: lure replies are folded, one reply's CA has a red pill ("different CA from the one @author posted"), a milestone post shows "claimed $10.6M · live $427k". Click a reply's chart link to GMGN: the Marshal icon goes red and a notification says it isn't the mint from the post you came from. Nothing to set up.

#### 2. Target user
Tech-bro desktop traders and builders (Chrome, Brave, Arc) who trade off crypto Twitter and X Communities. They pay by card, USDC, or by holding $MRSHL after launch. Mobile is out (the X app takes no extensions).

#### 8. Core logic
**Guard (gated, off-page):**
```
on x.com click(a) where a.href host in TERMINALS or post has a CA:
   m = mint_from_url(a.href) or post.raw_ca or link_text_ca          # never fetch t.co
   session.clicks.push({m, postId, author, ts: now}); idb.clicks.put(same)   # idb kept 90 days
terminal.content.ts (read-only): send {path: location.pathname, referrer: document.referrer, first_load} to background
background: p = resolve(path); c = newest click
   alarm only if c && now - c.ts <= 120 s && first route load since c
       && (referrer is t.co or x.com, or referrer == "") && p != c.m
   -> action.setBadgeText("!") red; notifications.create("Not the mint in the post you came from (@{c.author}, {age})")
   never write to the terminal DOM, read cookies/storage, touch the wallet or call terminal APIs
```
**Led-you-here (on device):**
```
opt-in: wallets[] = pasted base58 pubkeys (≤3); start = now; rpc = user_key ? helius : public
after each recorded click c on mint m: chrome.alarms at +2, +10, +30 min
poll(w): sigs = getSignaturesForAddress(w, {until: w.last_sig, limit: 25})
   for s in sigs: tx = getTransaction(s, jsonParsed)
      d = post − pre token balance where owner == w and mint == m          # owner, never signer
      if d > 0 and 0 <= tx.blockTime − c.ts <= 1800 s:
         spent = SOL out of w (minus fees), or USDC out → USD; any other quote → entry "unknown"
         attribute to the most recent click on m before blockTime; other clicks on m → "also seen from"
outcomes (cached; re-check +1 h, +24 h, then daily while held; ≤10 GeckoTerminal calls/min):
   crash_1h = min 5-min low in [t, t+1h] <= 0.2 × entry_usd
   held_24h = price(t+24h) >= 0.5 × entry_usd
   sol_result = SOL in from w's sells of m − spent (+ held tokens × DexScreener price, labelled "marked")
stamp(author) only with ≥1 matched buy; never upload, never a 0–10 score, never green, never on 0-buy accounts
backfill: same loop from install day only (no clicks exist earlier), with ETA and cancel
```
**Rings:** gain-line posts; 3+ accounts on one CA within 10 min = an edge; ring = 3+ accounts each with edges on 2+ CAs; join only on repeated links; 14-day decay. **Relay pair:** post q by b ≈ post p by a (normalised-text Jaccard ≥0.8 or the same number sequence), 0 < t_q − t_p ≤ 30 min, same CA → one source for counts, edge(a,b). **Linked to ring:** ≥2 shared windows with members of ring R on ≥1 CA but fails the 2-CA rule → grey "linked to ring R (1 coin)", never member, never red, 14-day decay.
**R11:** `post_ms = (id >> 22) + 1288834974657`; amber "linked post is {d} days older than this coin and doesn't name it" if `post_ms < mint_created_ms` and the post text names neither ticker nor CA.
**R12 (server):** one wallet (not the pool) holds ≥90% of supply, or two hold ≥49% each → red "one wallet holds N% of supply" (Trench Bot `clean-feed-build-rules.md`).
**Quote token:** read the pool's quote mint first; price non-SOL quotes via DexScreener/Jupiter; show "liquidity unknown", never $0.
