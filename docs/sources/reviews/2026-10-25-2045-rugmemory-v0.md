## Claude Code build brief (Rugmemory v1, self-contained)
**Build only after AT-K1, AT-K2 and AT-FP pass and Ethan picks it. Until then only the private replay runs.** This brief overrides idea bot's §15 where marked [PB].

**What it is.** A read-only REST API plus MCP server that a Solana trading agent calls before buying a pump.fun coin. It answers: do this coin's top holders, exact non-round holding sizes or deployer match coins in our memory that died (graded by code), and which ones? It returns facts with the dead coin named and linked. Never a score, probability, "safe", "buy" or "sell".

**Pitch [PB]:** "Every pump.fun dump script leaves a fingerprint." (Secondary: "Every pump.fun wallet now has a rap sheet.")

**Rivals to name in docs:** DeFade (closest), Cookin.fun, SolSentry (free), rugcheck, RugBurn, GMGN `token/security`, Bubblemaps. Positioning: "Use it next to your rug checker. It answers one question they don't: has this exact script run before?"

### v1 surface
| REST | MCP tool | Purpose |
|---|---|---|
| `GET /v1/coin/{mint}` | `check_coin` | Live top-holder read → wallet, exact-amount and deployer matches |
| `POST /v1/coins` (≤20 mints) | `check_coins` | Batch |
| `GET /v1/wallet/{address}` | `check_wallet` | Logged coins where the wallet was a top holder or deployer, with graded outcomes |
| `GET /v1/fingerprint/{amount}` [PB] | `check_amount` | Every logged coin that carried this exact raw amount, with outcomes |
| `GET /v1/outcome/{mint}` | `get_outcome` | Our code-graded outcome (cross time, peak, 24h/72h state, rule) |
| `POST /v1/credits/burn` | none | `{key_id, signature}` → verify burn, credit key |
| `GET /v1/usage` | `get_usage` | Quota, credits, memory size, `memory_since` |
Auth: `x-api-key`. Free key from `POST /v1/keys`, 1 per IP per day, 100 calls/day. MCP over Streamable HTTP (cloudflare/agents), all tools read-only.

**Response fields:** `memory` = `match | pending_match | no_match | unknown`; `match_strength` = `strong | weak | none`; `matches[]` each with `type` (`wallet | exact_amount | deployer`), the prior coin (mint, symbol, outcome, rule, drop), a one-sentence `reason`, Solscan/DexScreener links; `coverage` `{coins_in_memory, memory_since, no_match_is_not_safe: true}`; `official_mint`; `method_url`. Keep idea bot's JSON examples in §15.1 as the shape.

### Core logic (changes from §15.5 marked [PB])
- Holder read: `getTokenLargestAccounts` (top 20 token accounts) → `getMultipleAccounts` to resolve owners → drop off-curve owners (on the owner, not the token account) → drop `non_holder_wallets.json` entries.
- **Wallet match:** top 5 owners with share ≥1%. A prior counts as dumped only if graded `rug` by code. Operator rule as in idea bot §15.5 (a wallet also top holder on a live coin ≥24h old is a note, never a stamp).
- **Exact-amount match [PB, replaces "none live"]:** for owners with share ≥0.2% and a non-round amount (≥6 significant digits after stripping trailing zeros; 30,000,000 never matches), look up the raw u64 amount. `strong` if **≥2 priors are graded rug and 0 priors are graded held**, whatever the number of live priors. `pending` if fewer than 2 graded rugs. This lets fomo-type parallel templates count.
- **Deployer match:** `weak` only if ≥2 logged rugs. Document that SolSentry gives this free; it is context, not the product.
- `memory` = `match` if any strong, else `pending_match` if any pending, else `match` (weak) if any weak, else `no_match`.
- Users can never write memory: snapshot rows are written only by the pipeline.
- **Grader (by code, never hand verdicts):** at cross+24h and +72h, `rug` = drawdown ≥90% from reserve-backed peak, or base-pool quote reserve <10% of the cross reading; `held` = ≥$500k and reserve-backed; else `faded`. Non-SOL/USDC quotes valued through the quote token's own deepest SOL/USDC pool; never DexScreener `liquidity.usd`.

### Pipeline (Cron)
1. Every 5 min: Helius webhook stores newly migrated pump.fun → PumpSwap mints; DexScreener `tokens/v1` batch-samples (30 per call) until each crosses $500k or reaches 72h.
2. At the $500k cross: recompute cap from reserves × supply, snapshot holders + deployer, write `tw` (wallet), `ta` (amount), `td` (deployer) rows. Inputs frozen at that moment.
3. Every 15 min to 72h: peak tracking; grade at 24h and 72h.
4. **[PB] Backfill:** seed from every graduated pump.fun coin Helius can reach within the credit cap, not only Trench Bot's log, so the memory isn't 1k coins.
5. Daily export of D1 tables for Trench Bot; public `corrections` table.
