## What changed in v2 (each weakness in Project Bot's review)
1. **Differentiation vs Buddy and the OG-finders: pivoted.** Buddy ([buddycheck.xyz](https://buddycheck.xyz/)) already gives an automatic "VAMP: copy of $X, the OG sits at $77.4M MC" on trading pages. Its own FAQ says the OG is the "bigger, older one". Vamp Alert, OGfinder and Rick do the same in Telegram. So v2 **stops selling "which mint is real" as the product.** The lead is now the **X surface itself**: every CA, $ticker and token link in posts *and replies*, stamped automatically, plus scam replies folded with crypto-specific reasons. Three things are added that a trading-page or Telegram tool can't do, because they need the thread around the CA:
   - **Thread CA mismatch** (new): "different CA from the one @author posted in this thread". It runs locally with no API and doesn't need to know which coin is real.
   - **"Oldest ≠ deepest" disagreement stamp** (new): when launch order (the Buddy/Vamp Alert rule) and on-chain pool depth point at different mints, we say so instead of crowning either.
   - **Paid-only attention modifier**, computed from the posts the user has already loaded. Fund-name farms pass every holder test, and only this catches them (Trench Bot).
2. **"Real one is X" failed blind (0 of 4 right): fixed by shipping it off.** Growth Bot's rule, which Git bot, Trench Bot, X bot and Project Bot all agreed with: day one ships the **neutral grey "no confirmed real mint"**. The neutral stamp never hides or dims anything and never counts as a flag. `realCall` is behind a flag and turns on only if the frozen engine passes **Mint Seal Part B** once (AT-16). The v1 causes are designed out: no Jupiter-only calls, exact names after suffix stripping (so ELON never matches Dogelon), never credit a famous holder wallet (Trench Bot run 12: a copy parked 90% of supply in the real Kimchi creator's wallet), and two-way social links count as confirmation only.
3. **Missed competitors: added and re-swept by verdict, not surface** (Project Bot's lesson). v2's teardown includes Buddy, Vamp Alert/Solana OG Bot, OGfinder, Rick, Solami, Prysm /og, Moni Discover, CoinUFO and Rugcheck Bot. This run's sweep added **Futurepost** (warning labels for imposter/scam accounts next to names on X), **RugCheck's "Copycat token" flag** (driven by paid .token validation), **SafeCA** (auto-detects CAs on X with a 0-100 risk badge), **LARP Scanner** ($LARPSCAN on pump.fun), **Sharpe Rug Check** (copycat detection across 41 networks) and the **dafeiyu-cleaner** template (Bilibili bot badges).
4. **Token score 6: can't be raised much under Ethan's rules, and v2 says so.** Every rival with a token pays holders (Buddy 80% buyback-and-burn, Raindrop 50% of swap fees, fable 50% of API revenue). Ours can't. v2 tightens the token's jobs: hold for Pro, burn your own for deep checks priced under Rempart's US$0.15, and a separate burn flow, because x402 transfers tokens to `payTo` and doesn't burn them. The launch gate is ≥25 payers or ≥30% of installs active 3+ days a week, plus the legal consult. Realistic ceiling: 6-6.5.

## Product and UX
**First minute (AT-23: under 30s, ≤5 steps, no sign-up/wallet/X login):**
1. Click "Add to Chrome".
2. Open x.com. A one-line toast says: "Clean Feed is on · checks locally · only CAs leave your browser".
3. Every CA, $ticker and token link already has a pill. Grey means `no confirmed real mint · 1 of 12+ mints called $KIMCHI`. Amber means a factual warning (`oldest ≠ deepest`, `deployer 825 launches, 0 graduated`). Red means a rule hit (`name-bait: not made by SpaceX`, `different CA from the one @kimchi posted above`, `free-host page carrying a mint`).
4. Open any memecoin reply thread. Scam replies are already one grey bar: `Hidden · 10%-supply airdrop lure · same text as 9 others · Show · Not spam`.
5. Click any pill for the "why" panel: signals for and against, the family list (headed by the copy count and a "not ranked" note; the post's own mint first, labelled "the one in this post", then the rest alphabetical by mint, never sorted by liquidity or launch time by default, with liquidity, holders and launch time as user-sortable columns), the deployer record, a copy-CA button and Solscan links. There's no buy button.

**Popup:** three controls only: Strictness (Relaxed / Balanced default / Strict), Raw view, Pro.

**Advanced tech (what's new):**
- **Thread context as evidence.** The content script knows each post's conversation and author. It can say "this reply's CA differs from the CA the root author posted" and "this account dropped the same CA in 3+ conversations". It never has to know which mint is real.
- **Oldest ≠ deepest.** Launch order (rivals' rule) and on-chain pool reserves read from the pool account are both shown. When they disagree, the stamp says so.
- **Paid-only attention:** if a mint has ≥5 posts in the local 24h cache and 0 come from accounts that trip no shill rule, it gets `· risky: attention is paid callers only`.
- **Holder fingerprints from Trench Bot's log:** the 13.0-14.6% / 0.24% / 0.05% dump template, 1 or 18-19 first-10s buyers at 79.31%, and round-lot supply parked in a famous wallet (a copy tell, never a real signal).
- **Local-only mode:** text and link rules with zero network requests (AT-11).
- **Shadow-mode copy engine:** it computes "real" answers and logs them for the Part B test without showing them.

**What's hard:**
- X DOM churn (fail open, AT-25).
- Templates that rotate wording. v1 caught 2/17 new ones before v2's rules.
- Truncated family search. Both APIs cap results at 30 and 20 this run, so counts show as "12+".
- Copy-first families.
- Communities, where there is no test data yet.

**What a copycat could clone:**
- Buddy or SafeCA could clone the CA pill in a release.
- BotBlind or Raindrop could clone reply folding.
- Harder to clone: thread-context rules tuned on X bot's and Trench Bot's labelled data, the weekly pattern refresh, and published blind accuracy.

**Scores (mine; Project Bot scores officially):**
- **Innovation 6:** thread CA mismatch and oldest≠deepest are new.
- **Usability 8:** 5 steps, zero setup, no mobile.
- **Uniqueness 5:** nobody stamps every CA in X replies using thread evidence. It stays 4 under Project Bot's cap until the head-to-head.

## Token design on pump.fun ($CFEED, working ticker)
- **Jobs:**
  1. **Hold** to unlock Pro: unlimited stamps, Communities strict mode, copy alerts on coins you hold. Checked by a one-time wallet *message* signature on our website, never in the extension and never a transaction.
  2. **Burn your own** for deep checks (deployer funding graph, cross-chain impostors), priced at about US$0.03 equivalent, well under Rempart's US$0.15 (estimate), and for API credits. This needs its own burn flow: the user signs an SPL `burn` of their own tokens and the server credits the account after confirming the burn on-chain. x402 can't do this, because it transfers to `payTo`.
  3. **Lock your own to dispute a verdict:** returned if upheld, burned if frivolous. Nobody is ever paid from it.
- **Never:** holder payouts, revenue-funded buybacks, staking yield, creator-fee buy-and-burn, or profit promises. Card/USDC revenue never buys $CFEED.
- **Launch rules:**
  - pump.fun only.
  - **Mint and freeze authority off**, confirmed on-chain at launch.
  - **Holder Rewards OFF, Tokenized Agent buybacks OFF.**
  - **≤0.5 SOL labelled dev buy** from a published wallet, with a no-sell policy (est. 90 days).
  - No bundles, snipers or paid callers. Trench Bot found that attention which is only paid for now reads as a rug.
  - **Pin one official CA** on the site, the X account and the extension's settings page.
  - Launch only after ≥25 paying Pro users or ≥30% of installs active 3+ days a week, **and** the legal consult. Never during the 30-day test, and only once Ethan picks it.
- **On-chain fee flow and verification ([pump.fun fees](https://pump.fun/docs/fees), updated 17 Oct 2026, via Project Bot):**
  - Creating a coin carries no platform fee.
  - Bonding-curve trades pay 1.25%, of which the creator gets 0.30%.
  - After graduation, PumpSwap pays the creator a tiered fee (0.95% at 420-1,470 SOL market cap, falling to 0.05% above 98,240 SOL).
  - The web/mobile app adds a 0.45% Platform Fee, including on the creator's first buy.
  - Creator fees go to a **published operating wallet** used for hosting only. Anyone can verify it on Solscan.
  - The burn ledger is public: each credit links to its burn signature.
- **Dogfood:** on launch day the extension stamps every $CFEED copycat ("1 of N mints called $CFEED · not the pinned CA").
- **Comparable tokenised products:**
  - *Organic vs shilled is not measured by any bot for these.*
  - Barred patterns: Buddy (80% fee buyback-burn), Raindrop (50% swap fees to holders), fable (50% API revenue to stakers), Trenchee (fee rewards).
  - Patterns we may copy: Larpcheck (hold-to-access), The Codex (burn per question; self-reported numbers only).
  - Other examples: LARP Scanner ($LARPSCAN, pump.fun, mint/freeze disabled per Solana Tracker/Larpcheck pages) and Rugcheck Bot ($RC).
- **Legal line:**
  - ASIC [INFO 225](https://www.asic.gov.au/regulatory-resources/digital-transformation/digital-assets-financial-products-and-services): labels like "utility" don't decide the status, the token's rights do. Example 8 (a membership NFT that unlocks access) is "unlikely to be a managed investment scheme".
  - Say: "$CFEED unlocks Pro access in Clean Feed. It isn't an investment and gives no right to profits or revenue."
  - Never say returns, price, "burns raise the price", "not a financial product" or "ASIC-compliant".
  - No token talk on the CWS listing.
  - The A$300 consult (estimate) signs off. Not legal advice.
- **Token fit: about 6/10 (Project Bot 6).** Clean under the rules, but weaker pull than rivals' payout tokens.

### 5. Core detection logic (rules + pseudocode)
**Preprocessing and guards [X §2, TB §2]:**
```
body(t) = t minus leading @mentions, URLs, leading "Follow @x"
norm(t) = lowercase(body) with CA-><ca>, $TICKER->$t, digits->9, punctuation squashed
key(t)  = first 80 chars of norm(t) if words(norm) >= 5
WARNING = /fake|scam(mer)?s?|drain(er|ed)|wrong ca|not the real|beware|careful|stay safe|never connect|
           don'?t (buy|click|connect)|no (token|airdrop) announcement|whats? the ca|is this (legit|real)/i
GUARDS (always win): WARNING -> no lure/link/dup/burst rule; allowlisted official/news accounts never folded;
  user always-show never folded; post rules judge the post, never the coin; one post never trips a burst rule
```
**Post rules (fold, reason text in quotes):**
```
dup:        !WARNING && followers<20k && count(cache, same key, 24h) >= 3        -> "same text as N other posts"
same_ca:    reply && same author+CA in >=3 distinct conversations within 60 min  -> "same CA in N other replies"
            (own-timeline posts never count; fixes @ren_nevermind)
bare_tick:  reply, <=6 words, $TICKER, no CA; (same author+ticker in >=3 convs/60min) or (>=5 accounts, >=5 threads);
            apply to EVERY ticker in the reply                                     -> "$X dropped in N unrelated threads"
caller_ad:  funnel=/(alpha|private|vip) (tg|telegram|group|call)|copy trad|printing massiv|next 100x|gem loading|(dm|join).{0,25}(tg|vip)/i
            or brag=/\$?\d+(\.\d+)?[kKmM]\s*(→|->)\s*\$?\d+(\.\d+)?[kKmM]/ or (/\b\d{2,}(\.\d+)?\s?x\b/ && (CA||"mc"))
                                                                                    -> "caller ad: gain brag + TG funnel"
lure:       !WARNING && (/check (your )?eligib|(may|might|could|can) be eligible|allocation scan|scan (your )?wallet|claim up to|
            of (the )?supply (is being )?distribut|memepage|airdrop page|(explore|discover|meet|take a closer look at).{0,50}airdrop/i
            or (weak=/claim (your|now)|see what you can claim/i && followers<50k))  -> "airdrop / eligibility lure"
            lure memory: author with >=2 lures in view -> fold their other claim/airdrop replies
recovery:   /recover (your|lost|my)|recovery (agent|expert|service)|(contact|dm) @\w+.{0,60}(recover|hack|trace)/i -> "recovery-scam reply"
promo:      /new listing on dexvra|diamond tier|express listing|#bbvipks4/i       -> "paid listing / caller promo"
campaign:   >=5 accounts, generic praise under posts tagging same handle within 2 min -> fold "campaign replies"
paragraph:  same key from >=10 accounts in 24h with $t/CA                          -> DIM "promoted: copy-paste campaign"
bounty:     dup cluster && coin's linked account posts a pay-per-post offer        -> WARN "paid posts (disclosed bounty)" not fold [TB R8]
```
**Link rules (expanded URL only, never fetched) [TB R1-R2, X 2.6-2.7, Git §4]:**
```
FREE_HOSTS = netlify.app, vercel.app, pages.dev, workers.dev, github.io, web.app, firebaseapp.com, onrender.com, glitch.me,
             replit.app, surge.sh, herokuapp.com, framer.website, webflow.io, wixsite.com, carrd.co, fly.dev
host in FREE_HOSTS && base58(32-44) in path/query          -> red "free-host page carrying a mint"
host in FREE_HOSTS && sub ~ /claim|airdrop|drop|reward|eligib|allocation|bonus|giveaway|redeem/ -> red "claim page on a free host"
host endswith .memepage.io && host != www.memepage.io       -> red "MemePage claim subdomain"
eTLD+1 within edit distance <=2 (after homoglyph/punycode) of a protected brand, not the brand -> red "lookalike of <brand>"
brand in subdomain of unrelated domain                       -> red "brand name on unrelated domain"
MetaMask list match                                          -> adds to a reason, never alone
```
**Local pill rules (no API) [X 2.8, new in v2]:**
```
thread_mismatch: reply contains CA c with $T; root post (same conversation) by author A contains CA r with same $T; c != r
                 -> red "different CA from the one @A posted in this thread"   (factual, no claim about which is real)
two_cas:   one author posts >=2 different CAs for the same $T in 24h -> amber "posted 2 CAs for $T"
major:     $BTC/$ETH/$SOL/$WBTC/... next to a ...pump mint not in the canonical map -> red "not the real $T"
evm_sol:   0x address given for a Solana ticker -> amber "EVM address for a Solana ticker"
lookalike_handle: edit distance <=2 to an allowlisted project handle && >=3 link-only posts in view -> fold
```
**Coin rules (server, warn only, never hide a post) [TB R4, R5, R6, R10]:**
```
name_bait:  exact norm_name(ticker|name) in BRANDS (curated, exact match) -> red "name-bait: not made by <brand>"
template13: top3 non-pool/non-locker holders: 13.0<=h1<=14.6 && |h2-0.24|<0.03 && |h3-0.05|<0.01 -> red "dump template (13-14% wallet)"
buyout:     pumpdata first-10s buyers in {1,18,19} && share≈79.31% -> amber "curve bought by 1 wallet / linked factory"
            (bundle share alone is NEVER a flag: 13/22 lookups incl. survivors had 79.31%)
fake_fund:  /(national|american|united states|us|federal|global|institutional|russian).{0,20}(oil|dividend|reserve|trust|future|institution).{0,10}(fund|reserve)/i
            -> red "fake fund name: no real fund issues this"
paid_only:  posts_about(mint) in local 24h cache >=5 && organic==0 -> "· risky: attention is paid callers only"
```
**Copy engine (shadow until AT-16) [Git §3, TB §3, X §3, PB]:**
```
fam = exact_family( jupiter.search(T) ∪ dexscreener.search(T) )   # exact name/ticker after case, homoglyph and suffix strip
                                                                   # ("official","v2","2.0","(reversed)"); no substring; ticker-only
                                                                   # match with a conflicting name doesn't count; drop ~$0-liquidity mints
M_display = len(fam) + "+" if either search hit its cap (30 / 20)   # this run: caps hit for every ticker tested
for m in top10(fam by holders): read mint (age slot, authorities), pool/curve reserves ON-CHAIN, holders, graduated/migrated
votes (max one per family):
  A depth:    m has >=3x next mint's on-chain reserves AND most holders
  B curation: jupiter isVerified(m)                     # never the only agreeing vote
  C deployer: creator not a serial launcher AND distinct launch buyers > family median
  D social:   metadata X handle's bio/pinned post names exactly m, account checks pass,
              and no other family mint links the same account   # CONFIRMATION ONLY, never one of the 2 votes
never a vote: launch order (shown as a fact), DexScreener socials, liquidity.usd, any famous wallet that HOLDS m
              but didn't deploy it (Trench Bot run 12), Jupiter organicScore (real AOP = 0 this run)
candidate = the single m with >=2 of {A,B,C} agreeing, >=1 not B, and no family voting for another mint
stamp(c):  if realCall && candidate: c==candidate ? "real $T" : "copy · 1 of M+ called $T → real: abcd…wxyz"
           else: "no confirmed real mint · 1 of M+ called $T"
           + "oldest ≠ deepest" if argmin(createdAt) != argmax(reserves)
           migrations (SLERF/MYRO style): "moved to new mint" from a curated map
ONE rule for every group; never switch on group type (copy-first is a label, not an input)
```
