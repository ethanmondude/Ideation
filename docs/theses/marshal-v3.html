Marshal v3 ($MRSHL, formerly Clean Feed)

The X-native trench guard. It warns at the buy moment when the coin page isn't the mint from the post you clicked, remembers shill rings across days, and catches hijacked-account and QR drops that CA scanners never see

Executive summary

Product and UX

First minute (AT-23: <30 s, ≤5 steps, no sign-up, wallet or X login):

  1. Click "Add to Chrome". A toast says: "Marshal is on · checks locally · only CAs leave your browser".
  2. On x.com every CA, $ticker and token link has a pill (grey fact, amber warning, red rule hit). Scam replies are folded: Hidden · airdrop lure ("check memepage") · Show · Not spam.
  3. A post claims "$MIL JUST HIT $10.6M MC". The pill under it reads claimed $10.6M · live $427k (DexScreener, 14:29). Both are plain facts, with no verdict.
  4. Click a reply's chart link to GMGN. If that page's mint differs from the post's CA, a banner sits at the top: ⚠ Not the mint in the post you came from (@author, 3 min ago) · Why · Dismiss. The buy panel isn't covered or moved.
  5. Click any pill for "why": signals for and against, ring detail (handles, local only), deployer facts, a copy-CA button and Solscan links. There's no buy button, ever.

Popup: 3 controls: Strictness (Relaxed / Balanced / Strict), Raw view, Pro. Options page: Hold mode (opt-in), shared burst layer (opt-in, off by default), terminal permissions, always-show/hide lists, "what we send" log.

Advanced tech:

  • Post→terminal provenance: an outbound click writes {mint, postId, author, ts} to chrome.storage.session. The terminal content script reads location.pathname only (no cookies, storage, wallet or page APIs).
  • Rings that don't accuse: the gain-line shape is required (#K price, #X multiple, #m time). Without it, the timing-only rule chained a 14-account airdrop-lure farm plus bystanders on the busy Kimchi coin. An account joins a ring only after repeated links (edges on 2+ CAs), never from one shared window.
  • Shared burst layer without a handle list: the Worker hashes handles with its own daily-rotating secret key. The server keeps only per-coin HyperLogLog distinct-account counts per 10-minute window, and stores no hashes. Cross-day ring memory stays on each user's device. The day-one "coordinated copy" chip is the ring rule's live view ("11 accounts posted this CA with gain lines in 10 min · seen by Marshal users"). Privacy note: it's still opt-in data, because handles reach the Worker before hashing.
  • QR in images: jsQR in an OffscreenCanvas worker, downscaled to ≤800 px, ≤1 image per 200 ms, only on posts with a CA, claim words or a reply-thread lure. A decoded URL runs through the same link rules.
  • "Earliest seen by Marshal users": first sighting of a CA, from users' extensions only, labelled exactly that, never "first post on X".

What's hard: X DOM churn (fail open); first-sight weakness of the hijack tell (it needs ≥20 cached posts from that account); terminal URL formats (Axiom/Photon pair-vs-mint resolved with one getAccountInfo); busy coins for rings; Workers' shared outbound IPs for DexScreener per-IP limits.

What a copycat could clone: EDGERUN could add post provenance and the claimed-MC fact; Buddy could add the click memory; anyone can add jsQR. Hard to clone: the ring rule tuned on Trench Bot's and X bot's labelled rings and lure farms, the privacy design of the shared layer, and the weekly pattern refresh.

5. Core logic (rules + pseudocode)

Buy-moment guard:

on x.com click(a): if a.href (expanded, never fetch t.co) hosts in TERMINALS or post has CA:
    m = mint_from_url(a.href) or post.ca;  session.set(tabKey, {m, postId, author, ts:now})
on terminal page load / SPA route change:
    p = resolve(location.pathname)          # gmgn/pump: mint in URL; jup /swap: symbol→mint via Jupiter;
                                            # axiom/photon: addr → getAccountInfo → mint (owner = SPL Token) else pool base mint
    c = session.get(recent clicks ≤30 min, newest first)
    if c and p != c.m:  RED banner "Not the mint in the post you came from (@{c.author}, {age})" + family line
    elif p in family with M>1: GREY "1 of M+ mints called $T" (never green)
    Hold mode (opt-in): shadow-DOM overlay only on RED, only on GMGN/Jupiter/pump.fun; dismiss = 1 click
    NEVER: click/intercept page elements, read cookies/localStorage/wallet, call terminal APIs

Ring memory (local, per device):

obs = original posts (no RTs, no WARNING, no R8 disclosed bounty) with CA c and gain_line(text)
gain_line = /\$?\d+(\.\d+)?[kK]\b/ && /\b\d+(\.\d+)?\s?[xX]\b/ && /\b\d+\s?(m|min|mins)\b/
burst(c, w) = distinct authors with obs on c within a 10-min window w, size >= 3
edge(a,b) += 1 per distinct CA on which a and b share a burst      # one shared window = weight 1, never a ring
ring = connected component, >=3 accounts, every member has edges on >=2 distinct CAs
join: a new account joins only when it has edges on >=2 CAs with existing members (no single-window chaining)
decay: member out after 14 days with no new edge; ring retires below 3; record counts coins from last 30 days
chip: "pushed by a known ring · N accts · ring's coins: X rug (now <=10% of peak), Y still held"   # facts, never "scammer"
lure posts (lure regex) never form edges; they get the post-level lure label instead

Shared burst layer (opt-in, Worker):

client batch every 15 min: [{ca, handle, ts_bucket10, has_gain_line:true, status_id}]   # gain-line originals only
worker: if SET NX seen:{status_id} (TTL 2d) is new:
          h = HMAC_SHA256(daily_secret_key, lower(handle))       # key rotates 00:00 UTC; never stored; never sent to clients
          PFADD burst:{ca}:{bucket10} h ; EXPIRE 26h               # only HLL registers persist; no hash list
          SET NX first:{ca} {status_id, ts}                         # "earliest seen by Marshal users"
read: GET /v1/burst/{ca} -> {bucket10: PFCOUNT} ; chip "N accounts posted this CA with gain lines in 10 min · seen by Marshal users" when N >= 3
privacy line: "Opt-in. Handles you see are sent to our server, hashed with a key that changes daily, and only counts are kept."

Hijack tell + QR:

acct[h] = {posts_seen, ca_posts, bio_hash, loc_hash, first_seen}
if post has CA (text or QR) and acct.posts_seen >= 20 and acct.ca_posts == 0: amber "first CA seen from @h in N posts"
if bio_hash/loc_hash changed since last seen within 72h: add "· profile changed since {date}"
qr: images in posts with CA/claim words/lure context or from accounts with the flag above
    -> downscale <=800px -> BarcodeDetector || jsQR (timeout 150 ms -> skip, text rules only)
    -> decoded URL -> link rules (free host + mint, claim subdomain, lookalike) ; decoded mint -> pill
never upload images; GIF/video skipped

Claimed-vs-live MC:

claims = parse(text) for patterns like "$10.6M MC", "HIT $10.6M", "sitting at $X MC", "→ $X" (last value = claim)
live = DexScreener tokens/v1 marketCap (max over pairs for the mint) at render time, cached 60 s
pill: "claimed $X · live $Y (DexScreener, hh:mm AWST)"; amber if X/Y >= 2 or <= 0.5; nothing if no CA in post
example fixture: @AlphaPulsevw 2113877043767071199 claimed $10.6M vs live $426,772 at 14:29 AWST 24 Oct (~25x)
never on WARNING posts; never a verdict on the coin

Summary. Marshal is a read-only Chrome MV3 extension (Brave, Arc and Edge work; Firefox later) for desktop Solana traders who find coins on X and buy on GMGN, Jupiter, pump.fun, Axiom or Photon. On x.com it folds drainer, airdrop-lure and copy-paste shill replies into one grey bar with a reason, puts a factual pill on every CA, $ticker and token link, flags a reply CA that differs from the thread author's, shows "claimed $X · live $Y" when a post brags about market cap, marks a coin pushed by a shill ring it has seen before, and decodes QR codes in post images. When you click through to a coin page, it remembers the post, and if the page's mint differs it shows: "⚠ Not the mint in the post you came from (@author, 3 min ago)". No wallet access, no buy button, no sign-up, no LLM, and post text and images never leave the browser.

One-minute wow. Install. Open a memecoin reply thread: nine lure replies are folded, one reply's CA has a red pill ("different CA from the one @author posted"). Click a reply's chart link to GMGN: a red banner at the top says it isn't the mint from the post you came from. Nothing to set up.

Target user. Tech-bro desktop traders (Chrome, Brave, Arc) who trade off crypto Twitter. They pay by card, USDC or by holding $MRSHL after launch. Mobile is out (the X app takes no extensions).
