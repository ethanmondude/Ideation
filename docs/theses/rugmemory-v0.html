Rugmemory v0

Rap-sheet lookup for pump.fun coins, for AI trading agents (second thesis, build-ready draft)

25 Oct 2026, 8:45pm AWST 5/10

Executive summary

  • Pitch: "Every pump.fun wallet now has a rap sheet." It's an API plus MCP server an AI trading agent calls before it buys. It answers one bounded question: does this coin's top-holder set, exact holding sizes or deployer match coins in our log that died, with the dead coin named as proof? It gives facts plus a match reason. It never gives a score or price advice.
  • Edge (narrow): a memory built from our own labelled outcomes. That means dump wallets that come back on new coins (the GTA6 Coin wallets came from the Gemini rug, and the fomo top wallet is the run 27 IShowSpeed dumper), and exact repeat sizes that show up even when the wallet rotates (134,739,491.878 tokens on both the OpenAI and fomo coins). Those exact-amount sizes appear on 51 rug coins and 1 non-rug. Rugcheck works from contract and holder checks and doesn't track this. The fomo coin is the live case: rugcheck gave it one warning and no danger flag, while our memory matches it. The catch is that fomo's IShowSpeed prior hasn't died yet, so under graded outcomes it's only a pending_match today.
  • Biggest finding tonight: DeFade is closer than rugcheck. Its paid API (from US$35/month, checked 25 Oct) already sells /v1/wallet-reputation ("repeat offenders across past rugs"). It added /v1/exit-playbook today, 25 Oct, and has had deployer-reputation with funder history since 24 Oct. It also has a 15-tool MCP connector. What we'd still own is outcomes graded by code at a fixed horizon, exact-amount template memory, a free tier and an open method. That's thin.
  • Buyer: teams building Solana trading agents (crypto-native builders, Project Bot's call). AI labs are a bonus later, through an RL-environment package (§13), not v1. Builders already pay for this category: rugcheck sells API plans at US$40, 100 and 500 a month, DeFade at US$35–2,549, and Birdeye at US$39–499 (all checked 25 Oct). Those are price lists, not counts of customers.
  • Token job: after a free daily quota, a holder burns their own tokens from their own wallet to buy call credits. There are no payouts, no buybacks or burns funded from revenue, mint authority is off, launch is from a fresh wallet, and there's one pinned CA. Burns earn Ethan nothing. Running costs come from free tiers, and pump.fun creator fees go to hosting only.
  • Cost: A$0/month on free tiers with a hard A$25 cap. About A$50 up front without a token, and about A$276 with token and legal (est.).
  • Kill lines: AT-K1 is to beat rugcheck clearly at 50 outcomes, measured on discordant catches because 98.8% of logged coins are rugs. AT-K2 applies if DeFade's wallet-reputation/exit-playbook already catches ≥80% of our catches that rugcheck misses. AT-FP caps false matches at ≤1 in 20 survivors plus ≤1 in 50 random live mints.
  • Verdict: TEST, not pass. Confidence it reaches Ethan: ~20% (est.). It's cheap to keep testing because Trench Bot's head-to-head is already running. My expected scores are Inspo bar 6–7, Uniqueness 5–6 now that DeFade is named, and Token 6. Build nothing past the free private replay until AT-K1 and AT-K2 pass.

1. Problem and user

  • User: a builder running an autonomous or semi-autonomous Solana memecoin agent (ElizaOS/solana-agent-kit-style stacks, Telegram sniper bots with an LLM layer, personal Claude Code trading scripts). Before each buy the agent asks bounded questions, Jev-style. "Have these hands rugged before?" is one it can't answer from contract checks.
  • Pain, in our data: 939 of the 950 coins that crossed $500k in Trench Bot's log are rugs (trench-bot/latest.md, run 28). A $500k cap doesn't prove a coin is real. Contract checks pass most of them because pump.fun coins ship with mint and freeze revoked by default. The tell is in who holds, and the same operators reuse wallets and script sizes:
  • The fomo top wallet 8xA1VE… was run 27's IShowSpeed dump wallet. It now holds exactly 134,739,491.878 tokens, the same count the OpenAI dump wallet 2XqJKx… held in run 26.
  • GTA6 Coin 3P4y… reused the wallets from the Gemini rug (Garm AT-118).
  • Brand-bait exact repeat buy sizes: 48 of 48 rugs (chat). Exact-amount log total: 51 rug coins and 1 non-rug, the 30M amber case (latest.md).
  • Deployer Eu6e8H… launched 5 brand coins in about 6 hours (run 28).
  • Why an agent and not a human: a human uses DeFade's web page or Trench Radar's bubble map. An agent needs JSON in under a second, facts it can act on, and no captcha or login.

6. Token design (Ethan's rules)

  • Job: spend-to-burn for calls. The free quota is 100 calls a day per key with no token. Above that, a holder sends an SPL Burn of their own tokens from their own wallet, with a memo rm:<key_id>. The server verifies it (getTransaction: Burn instruction, mint is ours, the signer owns the burned account, amount ≥ pack price, signature not used before) and credits that key. Pack price is set in tokens at launch, for example N tokens = 10,000 calls (N is fixed at launch, est. US$5 equivalent). It is changed at most once a month with 7 days' notice. Credits can't be transferred or refunded and don't expire.
  • Optional, v1.1: stake-for-limits, where holding ≥X tokens in the wallet that signed raises the free quota. It's checked by balance read, never escrowed by us. No custody, no lockup program.
  • Never: holder payouts, revenue share, staking yield, buybacks or burns funded from revenue or creator fees, profit promises. Mint authority off. Launch from a fresh wallet, with one pinned CA in docs, MCP manifest and API responses ("official_mint"). Same rule set as Garm SPEC §8, cited rather than copied.
  • Honest token read: agents would have to hold a memecoin to buy volume. Many teams won't, so the token is a nice extra and the free tier carries adoption. Token score 6 (est.).

11. Defensibility

  • Weak to moderate. The data is public on-chain, so anyone with an RPC key can build the same memory from the same day. DeFade already has. What we'd own: (1) a head start of days, not months; (2) exact-amount template keys; (3) outcomes graded by code at a fixed horizon, published with method, so a builder can audit every match. Rivals give scores.
  • Operators can beat wallet memory cheaply by rotating wallets, which fomo already shows. Amount memory survives one rotation but not a change of script size.

12. Risks

  1. DeFade overlap (high). See AT-K2.
  2. Base rate (high). 98.8% of $500k crossers are rugs, so "always say rug" is ~99% accurate. The product has to be judged on discordant catches and survivor false flags, not accuracy (AT-K1, AT-FP).
  3. Low recall (high). Memory hits a small share of rugs: exact amounts on 51 coins, wallet stamps on 7 distinct coins from 4 wallets in runs 23–25 (Garm §5.3b). That's roughly ≤6% of the 939 rugs (est.). Most rugs are first-seen wallets.
  4. Thin seed. Most holder lists in the log come from rugcheck reports. Their reuse terms aren't confirmed (Garm §5.3b seed rule), so v1 seeds only from Helius/RPC holder reads.
  5. Licence. DexScreener bans resale of API data (checked 25 Oct), so we publish only derived facts and our own labels, never raw DexScreener fields. GeckoTerminal's free tier carries no commercial rights (CoinGecko licence FAQ, checked 25 Oct), so it's not used in production.
  6. False red on a live coin, from an operator or market-maker wallet that holds many coins. Mitigations: the operator rule, the non-holder list and the off-curve drop (cited in §15).
  7. Agents won't hold a memecoin. The free tier carries adoption, so the token may see few burns.
  8. Lag (medium). Template operators run coins in parallel, so a wallet's priors are often still alive when it shows up on the next coin, as fomo shows. Strong matches need a prior graded at 72h, so memory is slowest against the fastest operators.
  9. Defamation and safety framing. Facts about addresses only, with links and no adjectives about people.

13. Later packaging: RL environment (not v1)

Git bot's variant: "every pump.fun coin past $500k is a graded rug-avoidance task". It's rug-avoidance only until there are a few hundred survivors (Project Bot). Inputs are only what was visible at the $500k cross. The grader works out the label by code: rug = drawdown ≥90% from peak by 72h, or base-pool liquidity pulled (reserves below 10% of the cross reading); held = ≥$500k with reserves at 72h. Tasks are split by date, after the model's cutoff, and the grader rejects any answer that reads post-cross prices. Run the grader through a falsepass-style check before any sale. It reuses the v1 grader (§15.5) unchanged.

14. Kill or confirm

  • Kill on any of these: AT-K1 fails at 50 outcomes; AT-K2 shows DeFade catches ≥80% of our rugcheck-missed catches; AT-FP is breached; or Git bot's 10pm radar finds no real trading-agent project that would wire it in (Project Bot's condition 1).
  • Confirm (send to Ethan) when AT-K1, AT-K2 and AT-FP all pass, Project Bot's inspo-bar row is ≥7, and the replay cost stays at A$0.
  • Timing: Trench Bot adds about 17–28 $500k coins per scan, but outcomes need 24–72h, so ~50 graded outcomes takes about 2–4 days (est.).

15.5 Core logic

CHECK_COIN(mint):
  require mint resolves to a Token/Token-2022 mint (getAccountInfo owner)            # as Garm §5.0
  rows   = getTokenLargestAccounts(mint)                     # top 20 token ACCOUNTS
  owners = getMultipleAccounts(rows).parsed.owner            # resolve account -> OWNER (Garm AT-133)
  holders = [(owner, amount_raw, share)]
  drop owner if !isOnCurve(owner)                            # off-curve PDA drop, on the OWNER (Garm AT-131)
  drop owner if owner in non_holder_wallets.json             # same list + schema as Garm §5.3b (pump curve,
                                                             #   PumpSwap/DBC/DAMM authorities, exchange hot wallets)
  for (w, amt, share) in top 5 remaining with share >= 1%:
     priors = tw[w] where prior.mint != mint and prior.peak_reserve_backed
     live   = priors with share >=1%, drop known and < 0.90, age >= 24h
     if live: note "also top wallet on <live>"; continue      # operator rule (Garm §5.3b b), never a stamp
     dumped = priors with graded outcome == rug               # unknown or pending never counts
     if dumped: add match{type:"wallet", strength:"strong"}
     elif priors (all < 72h or ungraded): add match{type:"wallet", strength:"pending"}

  write snapshot rows (tw, ta, td) only via the pipeline, never from user calls     # users can't poison memory
