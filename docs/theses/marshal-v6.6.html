Executive summary

  • Problem: the scam sits between an X post and a buy. Trench Bot's log has 829 rugs among 841 coins that crossed US$500k. Run 23 was 24 of 24, and 10 of them were brand bait, two carrying dump wallets that had already emptied 5–6 earlier coins.
  • Product: Marshal is a free, read-only Chrome extension for x.com. It folds paid-caller replies with a reason, puts a fact pill by every Solana CA (never green), and warns when the coin page you open isn't the CA the post wrote. It names the earlier rug a coin's top wallet already dumped. New in v6.6: the stamp now skips dust and operator wallets, and Marshal reads on-chain who a "made for a dev" coin's fees really go to.

  • Cost against A$1,000: ~A$73 to day 30. A$449 lean / A$549 worst over 4 months, including ~A$300 legal (est.) and ~A$76 launch (est.). Running cost is capped at A$25/month.
  • Path to US$10k/month: about 667 active referred Axiom traders at an assumed US$15/month each (est.). Base case at month 12 is US$1.5–3.4k/month (est.).
  • Why now, edge, main risk: pump.fun's fees-to-GitHub feature and per-handle launchers (gitted, gitfees, PumpBoard, $HANDLES) are making borrowed-name coins at scale this week, and template dump wallets now repeat across 5–6 coins. Every rival either needs a tag or sits on a terminal or Telegram. The edge is automatic, deterministic stamps in the feed, built on public on-chain facts. Main risk: referral income may never cover costs, and R4b's exclusions are tuned on one run.
  • First move this week: Project Bot rescores, Trench Bot's runs 2–3 (12:00, 14:00) decide whether R4b goes red, and Ethan's name pick unlocks the Claude Code build. Product and user experience

First minute (AT-23: under 30s, at most 5 steps, no sign-up):

  1. Add to Chrome.
  2. A toast says "Marshal is on".
  3. Shill replies fold, each with a reason.
  4. A Riot Games-style CA shows red "same top wallet as (GxhR…), down 99.7% from peak · Why". Red only if r4b_red=true after the gate; grey until then.

Advanced under the hood: sharing-config PDA derivation (["sharing-config", mint] under pfeeUxB6…VojVZ), SocialFeePda decode (user_id, platform, total_claimed, last_claimed), stable GitHub numeric id to login, reserve-backed peaks, a wallet memory seeded from near-peak snapshots.

What's hard:

  • Pooled vaults: one GitHub vault can serve several coins (LEANREA's two mints share one). Show "shared by N coins" and never a per-coin claim amount.
  • Telling "claimed" from "fake claim": the claims-bot flags claim_social_fee_pda calls that pay 0. R13b reads total_claimed lamports, so a 0-lamport call never counts.
