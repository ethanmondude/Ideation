Ledgerport v2

The Sage 50 US MCP server and API for AI bookkeeping agents, with a backup-file fallback

24 Oct 2026, 9:00am AWST 6.5/10 Status: Pitched, awaiting Project Bot re score

Executive summary

  • Problem. Desktop Sage 50 US (formerly Peachtree, US$737 to US$2,130 a year) has no web API. The only way in is a 32-bit .NET SDK on the Windows PC that holds the books (Apideck guide). AI bookkeeping and AP agents that work on QuickBooks Online and Xero can't reach these books. Nobody offers a Sage 50 US MCP server (GitHub and vendor checks above).
  • Product. "The Sage 50 US MCP server": a signed Windows connector the bookkeeper installs once, plus an MCP server and REST API with typed TypeScript and Python SDKs, plain-English errors and a hosted "connect your Sage 50" link. Sage-hosted customers get a read-only fallback: upload a .ptb backup and query it.
  • Who pays and how much. Small SaaS and AI-bookkeeping teams with fewer than about 25 Sage 50 US customers, by card. Free sandbox, then US$49 per connected company file per month with a US$99 monthly minimum (2 files included). That matches Conductor's price and sits under Apideck's US$599 floor (pricing). An x402 USDC price per backup read goes to agents that need a one-off read.
  • Token's job. None that's real. These buyers won't pay for their integration in a memecoin, and gating the free sandbox would choke the funnel. Token fit is about 2/10, so this fails Ethan's token gate, as well as the audience gate.
  • Total cost vs A$1,000. About A$490 before the first revenue (VM, domain, hosting, code signing) and about A$860 over 4 months including a A$300 legal consult (estimates). If Sage requires its paid developer programme, the pre-revenue figure rises to about A$985, right at the cap.
  • Path to US$10k/month. About 205 files, or about 35 teams at about 6 files each. The base case is about US$6.0k MRR at month 12 (123 files, 34 teams; estimate). Reaching US$10k takes about 16 to 20 months, or one AP or payments customer with 40+ Sage 50 US users.
  • Why now, edge and main risk. Conductor proves the model: US$44,359 MRR, Stripe-verified. Apideck is still "In development", and nobody owns "Sage 50 US MCP". The edge is being the first self-serve, agent-first specialist. Main risk: Apideck ships into the same searches with an MCP and lower prices at scale, while Sage moves desktop customers to a hosted edition where connectors can't run.
  • First move this week, and verdict. Nothing external. If Ethan keeps it as a benchmark, the first step is a private 3-day spike on the sample company: read customers and invoices through a local MCP tool, then create an invoice. Verdict: PASS as a coin thesis, because it's outside Ethan's rules. Keep it as a non-coin benchmark if Ethan wants one. As a plain bootstrapped business it's TEST, at about 45% confidence (unchanged).

Problem and user

  • Buyer (pays): the founder or CTO of a 3 to 50-person AI-bookkeeping, AP-automation, expense or vertical SaaS company whose US customers run Sage 50 Pro, Premium or Quantum. They pay for developer infrastructure by card.
  • End user (installs): the small business's bookkeeper or office manager, on a Windows PC or a third-party host.
  • Today they: build a 32-bit .NET Framework 4.8 connector themselves (handling CompanyLocked, per-company approval prompts, yearly releases and conversions), use read-only ODBC (which "does not work with 64-bit programs"), use fragile CSV, refer customers to Commercient (US$299 a month on BigCommerce) or Zynk Workflow, or say no (all from Apideck unless linked). Apideck's own advice: "Ask every prospect whether they run Sage 50 on their own machines or on Sage 50 Cloud before you quote" (same guide).
  • Why agents make it sharper: an AI bookkeeping agent can't open a Windows desktop app. On the sister platform, Conductor's users describe an agent migrating their QuickBooks Desktop integration "in one afternoon", and others say "Your MCP is amazing" (conductor.is).

Product and UX

  • First minute (developer): sign up → copy a sandbox key → npx the MCP server, or paste the hosted MCP URL into Claude, ChatGPT or Cursor → ask "list overdue invoices in the sample company" → the answer comes back from Sage's sample data. No sales call.
  • First minute (bookkeeper): open the auth link → download the signed connector → approve the access prompt in Sage 50 (on-screen guide) → see "connected".
  • MVP stack:
  • Connector: C# .NET Framework 4.8 x86 Windows service, outbound WebSocket only, retries on CompanyLocked, writes queued while the PC is off.
  • Cloud: TypeScript (Hono), Postgres (Neon), Postgres job queue, Fly.io.
  • Interfaces: OpenAPI with generated SDKs, an MCP server on the same endpoints, and Stripe Billing on active files.
  • Backup path (phase 2): upload a .ptb → a parser in an isolated worker → read-only snapshot tables → the same MCP tools with freshness: <backup date>.
  • Week by week: 1. Spike on the sample company: reads, plus create and read back one invoice. 2. Relay and queue, API keys, auth link, read endpoints, MCP tools. 3. 3 writes (invoice, bill, payment), error catalogue v1, TypeScript SDK, signed installer. 4. Billing with the US$99 minimum, Python SDK, docs, 2 design partners.
  • Webhooks and the backup parser come later, only on demand.
  • Advanced tech: MCP tool design that keeps agents safe on someone's books (read-only by default per company, write scopes per tool, dry-run previews of every write, and an audit log returning Sage's transaction IDs).
  • What's hard: the Windows service (sleep, locks, antivirus flags), Sage SDK quirks (cash-basis companies can't create invoices, audit-trail gaps, one company open at a time), yearly releases, the closed .ptb format, and US support hours, which are 9pm to 7am in Perth.
  • Cloneable: the REST wrapper. Not quickly cloneable: a signed connector proven in real offices, the error catalogue, release testing, and SDK lock-in.

Agent distribution

  • MCP server (lead channel): hosted at a URL plus an npx package. Read-only by default, with per-tool write scopes and dry-run previews. Build cost: about 3 days, on the same endpoints. A$0 extra.
  • x402 pay-per-call: a stateless "read this .ptb backup" endpoint (an agent uploads a backup and gets trial balance, aged receivables and GL JSON), priced in USDC and only for one-off reads with no account. Build cost: about 2 days once the parser exists. This fits x402 well because there's no connection to keep alive. It's not a token job.
  • Grok Bot template: "Connect a Sage 50 US sandbox to your agent". It walks a developer from key to first query. Build cost: about 1 day, following pumpdata.fun's template model (template).
