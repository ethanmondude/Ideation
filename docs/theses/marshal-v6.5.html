Product and user experience

First minute (AT-23: <30 s, ≤5 steps, no sign-up, wallet or X login): add to Chrome → toast "Marshal is on · checks locally · only CAs leave your browser" → shill replies fold with a reason → each CA gets a grey/amber/red fact pill (never green) → a coin named after @someone shows "named after @someone · no post from @someone with this mint seen" → a coin whose top wallet repeats shows red "same top wallet as Gemini (DhUh…), down N% from peak · Why" (N computed live). Advanced under the hood: deterministic rule engine (AT-112), X snowflake dating, post-to-tab provenance, server-side wallet memory keyed by public holder addresses, on-device ring graph and click history. What's hard: X DOM churn; deciding which handle a coin is "named after" without false matches (R13 requires the handle in the coin's own metadata link, or name/ticker equal to the handle, case-insensitive, ≥4 chars); wallet memory must exclude pools, curves, lockers and exchanges (reuse R12's exclusion list). Copycat risk: SiftscanBot or EDGERUN could add R13 in weeks. Not clonable quickly: each user's ring memory and click history, and a wallet memory that grows with every coin Marshal users check. Scores (mine; Project Bot scores officially): Innovation 7.5 (+0.5 for R4b wallet memory and R13), Usability 8 (unchanged, automatic, no tagging), Uniqueness 6.5 (+0.5: R13 has no rival found; the project-pinned check lost its uniqueness to Siftscan, which v6.4 hadn't claimed in v1 anyway).
