Stencil (working name, $STNCL)

Every website is now an API, in your own browser — v0

25 Oct 2026, 10:30pm AWST 5.3/10

Executive summary

  • Problem. Agents can't use the sites people actually work in (supplier portals, admin panels, SaaS tools without an API, internal tools). Agent-driven browsing reasons through every page, so it is slow, costly and "breaks with the smallest UI change" (@OPuzanov). The hosted fixes ask you to hand over your passwords and 2FA secrets (Pomerado saved logins). Builders say "Kill, for now: anything with a login" (@shawnAIOperator).
  • Product. A Chrome extension plus a local MCP bridge. You do a task once in your own logged-in Chrome. Stencil saves it as a typed, deterministic MCP tool file (inputs, output schema, read or write authority) that Claude Code, Cursor or any MCP client can call. Runs happen in your real session, so passkeys, SSO and "Sign in with Google" just work and no credential ever leaves your machine. A paid relay lets cloud agents call those tools through your browser. A shared library holds public tools whose "verified" stamp comes from signed pass/fail receipts from real paying callers.
  • Who pays and how much (estimates). AI-agent developers and power users. Free: unlimited local record and run. Pro US$15/mo: relay endpoint for remote and cloud agents, 300 auto-repairs, private packs. Team US$49/mo. Card first; the token is an alternative way to pay.
  • Token job (no payouts to anyone). Burn $STNCL per relay or library call past the free quota (user-funded consumption, never bought with card revenue). Authors lock $STNCL to list a library tool as "verified"; a failed verification burns the slashed stake. Fixers earn free credits and ranking, never tokens.
  • Cost vs A$1,000 (estimate). About A$120 to day 30 and A$420 to A$560 over 4 months (Chrome Web Store US$5, domain, Cloudflare Workers paid US$5/mo, LLM for tool generation and repair capped at A$40/mo, Browserbase only after revenue).
  • Path to US$10k/mo. About 450 Pro plus 60 Team in 12 months, through Claude Code and Cursor communities, a Show HN, a one-command import for workflow-use users and the public library as SEO. Realistic month-12 range US$2k to US$6k; US$10k is the stretch.
  • Why now. MCP is the standard socket for Claude Code and Cursor; Chrome's WebMCP origin trial (Chrome 149 to 162, ends 30 Mar 2027) makes "sites as tools" mainstream, but most sites will never publish tools. The category already gets inspo-level reach: Gumloop's Agent Browsers launch hit 413,614 views (post).
  • Edge and main risk. Edge: "your session, never your password" plus deterministic replay plus a verified-by-real-calls library. Main risk: Pomerado (YC, MIT, free Personal plan of 100 runs a day and 10 builds a month, self-healing on Cloud) already ships most of the job; its runtime can already attach over CDP to a Chromium a host owns, so an "own Chrome" mode is a short step for them.
  • First move this week (free, private). A 2-day spike: record 10 logged-in tasks across 10 sites (SSO, passkey and Google sign-in among them) and replay each 20 times; pass line 9 of 10 tools at 95% or better. Same 10 tasks on Pomerado free to count how many it can't sign in to.
  • Verdict: TEST, about 25% confidence. It clears the inspo bar, but Uniqueness rests on one wedge (own session, no credential handover) that Pomerado could close. Kill line K1 below.

Product and user experience

First minute.

  1. Install the extension and run npx stencil init (adds the local MCP server to Claude Code or Cursor in one command; the extension pairs over native messaging).
  2. Click Record, do the task (e.g. "download this month's invoices from the supplier portal"), click Stop.
  3. Stencil shows a draft tool card: name, typed inputs it guessed (dates, IDs, search text), output schema, authority (read or write), and a dry-run button. Accept.
  4. In Claude Code: "get me October invoices from Acme portal" calls acme_invoices({month:"2026-10"}) and returns JSON in about 2 to 5 seconds (target, AT-3).

Advanced under the hood.

  • Each step is stored with a ranked set of locators (accessibility role and name, text, test ids, structural path, last-known coordinates) and a post-condition (what must be true after the step). Replay picks the first locator that satisfies the post-condition.
  • Typed parameters are inferred from what the user typed or chose and generalised (a date picker becomes date, a dropdown becomes an enum of the options seen).
  • Output extraction is recorded by pointing at the result (a table, a list, a value); Stencil writes a JSON Schema and an extractor.
  • Write tools carry a risk flag and a confirm step by default (the agent must pass confirm:true on irreversible actions such as submit, pay or delete).
  • Repair: on a failed post-condition, a small model gets the step intent, the old locator bundle and the current accessibility tree, proposes a new locator, and verifies it against the post-condition. Repair is local with the user's key, or paid credits on Pro.
  • Relay (Pro): a hosted MCP endpoint per user; calls are queued to the user's paired Chrome over an outbound WebSocket. Only the call inputs and outputs transit; cookies and credentials never leave the browser.

What's hard. Robust replay on SPAs, iframes and shadow DOM; file downloads; Chrome Web Store review for an extension with broad host permissions; sites whose terms forbid automation (the user is automating their own account, but we must say so and never stealth past bot checks).

What a copycat could clone. The recorder and replay in weeks. Harder to copy: the library's receipt history and verified stamps, and trust (open-source extension, published security model).

Innovation / usability / uniqueness (self-rating, Project Bot to score). Innovation 6, Usability 8, Uniqueness 5 (one wedge; Pomerado close).

Token design on pump.fun ($STNCL, working ticker)

  • Job 1, pay per call: relay and library calls past the free quota cost credits. Users can buy credits by card (Stripe) or burn their own $STNCL at a published credits-per-token rate. Card revenue is never used to buy or burn tokens (Ethan's no revenue-funded burn rule).
  • Job 2, stake to verify: listing a public library tool as "verified" requires locking a stake (e.g. the token amount worth about US$20 at lock time). If verification fails (rules below), 20% of the stake is burned, never paid to anyone. An honest unlock returns the stake with no yield.
  • Fixers: whoever ships a repair that restores a failing verified tool gets free credits and a ranking boost, never tokens.
  • Verification rules (Project Bot guardrails built in):
  • Receipts carry only tool id, version, pass or fail, schema-match yes or no, duration and a caller signature (an ed25519 key per install). Never page content; logged-in results stay private.
  • Success counts by distinct paying callers (paid plan or burned tokens in the last 30 days), excluding the author's accounts and any caller linked to the author's payment method or wallet. One receipt per caller per tool per day.
  • Public-page tools are also re-run nightly from a hosted browser; logged-in tools are verified only by real receipts plus author-triggered re-runs from the author's own browser.
  • Launch hygiene: launch only after the first paying users; mint authority off; small labelled dev buy; no bundles; pump.fun Holder Rewards and Tokenized Agent buybacks off; pin one official contract address from day one (full mint in the launch post and in the extension's About page); launch from a fresh wallet; public repo; creator fees as a bonus only, never promised.
  • On-chain fee flow and verification: burns go to the token's burn (Token-2022 or SPL burn instruction) with the call id in a memo, so anyone can match burns to calls; a public page lists daily burns and stakes slashed.
  • Legal line (Australia and US, not legal advice): the token is a consumable access credit; there are no payouts, yields, buybacks or profit promises, and staking returns only the user's own tokens. That keeps it away from a managed investment scheme or financial product under the Corporations Act as ASIC applies it (see ASIC INFO 225 on crypto-assets) and from US investment-contract framing. Get a short legal read before launch; marketing must never talk about price.

Build brief for Claude Code

MVP scope. Chrome MV3 extension (recorder, replayer, tool card UI), a local MCP server (Node, stdio) paired with the extension over native messaging, a tool-file format, the workflow-use importer, a hosted relay (Pro), and a small public library with receipts and stakes. No cloud browser for logged-in tools.

Features in build order.

  1. Recorder: capture clicks, typing, selects, navigation, downloads; per step a locator bundle and post-condition.
  2. Tool file *.stencil.json: name, description, version, origin, authority (read|write), inputs (JSON Schema), output (JSON Schema), steps[], confirmSteps[].
  3. Replayer in the user's tab (opens a background tab, runs steps, returns output).
  4. Local MCP server: exposes each tool file in ~/.stencil/tools/ as an MCP tool; npx stencil init writes Claude Code / Cursor config.
  5. Tool card UI with dry-run.
  6. workflow-use importer.
  7. Repair (local key first, hosted credits on Pro).
  8. Relay: hosted MCP endpoint (Cloudflare Worker + Durable Object per user), outbound WebSocket from the extension, Stripe billing.
  9. Library: publish public tools, receipts, verified stamps, nightly re-runs of public-page tools.
  10. Token: burn-for-credits and stake-to-verify (Solana program or SPL burn + memo; stakes in an escrow PDA with no yield).

Architecture and stack. TypeScript throughout; MV3 service worker plus content scripts; Node 20+ MCP server (@modelcontextprotocol/sdk); Cloudflare Workers, Durable Objects, D1; Stripe Checkout; Solana web3.js for burns and stakes; small model via any OpenAI-compatible API for draft schemas and repair.

Data sources, APIs, costs and terms. Chrome Web Store (US$5 one-off); Cloudflare Workers paid (US$5/mo); Stripe (standard fees); LLM API (cap A$40/mo); Browserbase Developer US$20/mo only for public-tool nightly runs, after revenue. Respect each site's terms; no captcha solving, stealth or proxy rotation.

Core logic (rules and pseudocode).

record(step):
  bundle = [roleName(el), text(el), testId(el), cssPath(el), xy(el)]
  post   = observe(after: url change | element appears | value set | download started)
  save {action, bundle, post, paramRef?}

replay(tool, inputs):
  validate inputs against tool.inputs
  for step in tool.steps:
     el = first loc in step.bundle where resolve(loc) and not ambiguous
     if none: el = repair(step) if repair allowed else fail(step)
     if step in confirmSteps and inputs.confirm != true: return needs_confirm
     do(step.action, el, bind(step.paramRef, inputs))
     if not waitFor(step.post, 10s): fail(step)
  out = extract(tool.output); validate out against tool.output
  emit receipt {tool, version, pass, schemaMatch, ms, sig}   # no page content
  return out

verified(tool) over last 7 days:
  callers = distinct paying callers with receipts, excluding author-linked
  verified if callers >= 5 and pass_rate >= 0.90 and stake_locked
  if callers >= 5 and pass_rate < 0.60 for 72h and no new version within 72h:
     burn 20% of stake; remove stamp

UI and first-minute flow. As in "First minute" above; the tool card shows inputs, output preview, authority and a "used by N paying callers this week" line for library tools.

Token integration steps. Card credits ledger first; then a burn endpoint that verifies an on-chain burn with memo stencil:<user>:<credits> and credits the account; then stake escrow with unlock after a 7-day cooldown and the slash rule above. Mint authority off; official CA pinned in the extension.

Acceptance tests (numeric pass lines).

  • AT-1: 10 recorded logged-in tools on 10 different sites (at least 3 using SSO, passkey or Google sign-in) each replay 20 times; at least 9 of 10 tools reach 95% success.
  • AT-2: no credential, cookie or page content leaves the machine on a relay call (proxy capture shows only inputs and outputs); 0 leaks.
  • AT-3: median replay time under 5 seconds for 5-step read tools.
  • AT-4: after a simulated layout change (renamed classes, moved button) on 10 tools, repair restores at least 7 within 60 seconds each.
  • AT-5: npx stencil init to first successful tool call in Claude Code in under 3 minutes for a new user (5 of 5 testers).
  • AT-6: receipts from the author's own and payment-linked accounts never count toward verified (3 of 3 sybil attempts rejected).
  • AT-7: write tools never perform a confirm step without confirm:true (0 of 50 attempts).
  • AT-8: workflow-use import converts at least 8 of 10 sample workflows into working tools.
  • AT-K1 (kill line): Pomerado free plan check (K3) recorded in the TESTLOG before any build starts.

Claude Code build brief (Stencil v1, refined; self-contained)

Summary. Stencil turns any website you're signed into into a typed tool your AI agent can call, without handing over a password. You do the task once in Chrome; Stencil watches the page's own network requests, works out which request does the job and which fields are inputs, and writes a *.stencil.json tool file. Your local MCP server then runs that tool by replaying the site's first-party HTTP calls from inside your Chrome session (same cookies, same origin), falling back to DOM replay when a site doesn't expose a clean request. Wow moment (one minute): record "download October invoices" on a supplier portal, and Claude Code calls acme_invoices({month:"2026-10"}) and gets JSON back in under a second. Target user. Developers and technical operators wiring Claude Code, Cursor or custom agents into sites with no API; secondary: crypto power users automating dashboards they're logged into. Where it runs. Chrome MV3 extension (recorder, runner, tool cards) + local Node MCP server (stdio) paired over native messaging. Optional hosted relay later.

v1 features in build order (acceptance criteria):

  1. Network recorder: during Record, capture requests via chrome.debugger (Network domain) on the recorded tab only, plus DOM actions (click, type, select, navigate). Drop analytics, pixels, polling. AC: on 10 sample sites, the request that carries the result is in the capture 10 of 10 times.
  2. Request compiler: find the request whose response holds the selected result; map user-typed values to request fields (record the task twice with different inputs and diff, as Unbrowse does); trace tokens/IDs (CSRF, account IDs) back to the response that produced them; output a request chain. AC: 7 of 10 tasks compile to a chain that replays with new inputs.
  3. Tool file *.stencil.json: name, description, version, origin, authority (read|write), inputs (JSON Schema), output (JSON Schema), mode (http|dom), requests[] or steps[], confirmSteps[], signature. AC: validates against a published JSON Schema; diffs cleanly in git.
  4. Runner: executes http mode from an extension context on the site's origin (so the browser attaches its own cookies; cookies are never read or exported), else dom mode with ranked locators and post-conditions. AC: http-mode median under 1s; dom-mode median under 5s for 5-step reads.
  5. Local MCP server + npx stencil init (writes Claude Code/Cursor config, loads every tool in ~/.stencil/tools/ and ./.stencil/ in the repo). AC: new user reaches first successful call in under 3 minutes, 5 of 5 testers.
  6. Tool card UI: inputs, output preview, authority, dry run. Write tools require confirm:true. AC: 0 of 50 confirm steps run without it.
  7. stencil test CLI for CI: runs each tool's saved example and checks output against schema. AC: exits non-zero on schema mismatch.
  8. Repair (BYO key): on failure, a small model proposes a new locator or request mapping and verifies it. AC: 7 of 10 simulated breakages fixed within 60s.
  9. Importers: workflow-use JSON and Integuru-style HAR. AC: 8 of 10 samples become working tools.
  10. Later (Pro, after first users): hosted relay (Cloudflare Worker + Durable Object, outbound WebSocket from the extension); credits; token.

Out of v1: cloud browsers, password storage, captcha solving, stealth or proxy rotation, a public library with verified stamps (Unbrowse already has one), Windows-only features, voice. Data sources and APIs (verified exist): Chrome extension APIs (chrome.debugger, native messaging, MV3); @modelcontextprotocol/sdk; Chrome Web Store developer registration (one-off fee, about US$5, not rechecked tonight); Cloudflare Workers paid US$5/mo for the relay (idea bot figure, not rechecked tonight); Stripe Checkout; any OpenAI-compatible small model for repair (cap A$40/mo). Stack and layout: TypeScript monorepo: extension/ (service worker, content scripts, side panel), mcp/ (Node 20 stdio server, CLI init|test|import), schema/ (tool-file JSON Schema), relay/ (Worker, later), examples/. Data model: ToolFile (above); Recording {id, origin, actions[], requests[] (url, method, headers minus cookies, body template, response sample hash)}; RunReceipt {tool, version, pass, schemaMatch, ms} with no page content. Token integration (after 50 paying users, Ethan's call): $STNCL on pump.fun; burn instruction with memo stencil:<user>:<credits> verified by the relay to credit the account; no payouts, yield, buybacks or revenue-funded burns; mint authority off; one pinned CA in the extension About page.
